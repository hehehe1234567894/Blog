这个博客是我自己写主题、自己配部署搭起来的，所以出问题基本只能自己修。
这篇文章有两个用途：**告诉你怎么把问题反馈给我**，以及**把我最近半月修掉的 bug 摊开记一遍** ——
写清楚「现象 → 根因 → 怎么修 → 怎么验证」，一是给自己留档，二是这些问题大多不是孤例，
如果你也在搭 Hugo 博客，说不定能直接抄走结论。

## 一、怎么反馈问题

两个入口，随便挑一个：

1. **GitHub Issues**（推荐，能贴图、能追溯、能收到通知）：
   [github.com/hehehe1234567894/MySuperBlog/issues/new](https://github.com/hehehe1234567894/MySuperBlog/issues/new)
2. **文章底部的评论区**（基于 giscus + GitHub Discussions，用 GitHub 账号登录即可发言）：
   任意一篇文章拉到底就是。只想说一句、不想开 issue 的话走这里最省事。

### 提问题时最好带上这几项

有这几样，我基本能一次定位；缺了就得来回问几轮：

- **现象**：你看到什么、期望是什么。比如「点汉堡菜单没反应」比「菜单坏了」有用得多。
- **页面地址**：把出问题的那个 URL 贴上来（例如 `/posts/xxx/` 或首页）。
- **设备**：手机还是电脑，大概的屏幕宽度或机型。这个站的手机端和桌面端走的是两套布局，
  差别很大 —— 下面 9 个问题里有 4 个只出现在手机窄屏。
- **深浅色**：右上角切换是浅色还是深色。评论区的配色、遮罩强度都跟这个有关。
- **截图**：一张图胜过三句话，尤其涉及「位置偏了 / 挡住了 / 看不清」这类视觉问题。
- 时间允许的话补一句**能不能稳定复现**（每次都这样，还是偶发）。

## 二、最近修掉的问题（新的在上）

下面每条都附了提交号，可以在仓库的 commit 历史里直接搜。

### 1. 手机首页的封面把角色切得只剩躯干

- **现象**：手机打开首页，hero 大图里只能看到角色的手和裙摆，**头部整个在画面外**，
  而且文章标题正好压在躯干上。
- **根因**：是图片比例问题，不是位置没调好。封面原图 1920×1200（比例 1.60），
  手机竖屏的 hero 窗口是 0.52 左右。`cover` 缩放后，画面实际只露出原图
  **x 35.5% ~ 63.8%** 这一条竖带；而角色的脸在 **x 63% ~ 74%** —— 正好卡在窗口右边界之外。
  也就是说，`background-position` 怎么调（我试了 0/8/12/18/22/26/30/38%）都取不到脸，
  因为横向范围根本不够。顺带量了一下原图各横带的平均亮度，整张都是亮云亮雾，
  也没有「安静区域」可以让标题落上去。
- **怎么修**：不再拧位置，改成给窄屏**单独一张裁切块**：从原图裁
  `x 864~1910 / y 120~940`（1046×820，比例 1.28），这一块完整包含角色的脸、左侧留出天空；
  再把窄屏 hero 高度从 88svh 降到 78svh，让窗口比例落进裁切块里，于是只裁上下、不裁左右。
  CSS 上就是：

  ```css
  .hero::before {
    background-image: var(--hero-img-mobile, var(--hero-img));
    background-position: 78% 32%;
  }
  ```

  拿不到 `--hero-img-mobile` 时自动回退桌面封面，所以没配裁切块也不会坏。
- **怎么验证**：在 390×844 / 390×700 / 390×1000 三档手机高度下截图对比，
  三档都是「头部与面部完整 + 标题落在她下方的留白处 + 卡片区首屏露出」；
  同时确认桌面 1280 与 1920 下仍是原来的 `50% 42%`，没有被改动。
- 提交：`54113cc`、`de4cc92`

### 2. 搜索页变成了一篇空文章，而且汉堡菜单点不开

- **现象**：打开 `/search/`，看到的不是搜索框，而是一篇标题叫「搜索」、日期显示
  `0001-01-01 · 0 分钟 · 0 字` 的文章，下面还有「上一篇 / 下一篇」。
  同一页上右上角的汉堡按钮点了没反应 —— 菜单闪一下就关。
- **根因**：`content/` 下有**两个文件都声明了同一个 URL**：

  ```yaml
  # content/search.md
  url: "/search/"
  # content/search-lite.md
  url: "/search/"
  ```

  Hugo 遇到同 URL 冲突时**不报错、不告警**，谁赢取决于构建环境里文件的遍历顺序 ——
  所以本地怎么构建都正常，线上（GitHub Actions）却是坏的。后果是同一个 URL 被两个模板
  各渲染了一遍：搜索模板渲染出搜索框，博客文章模板渲染出那篇 `0001-01-01` 的空文章。
  更隐蔽的是，**脚本也被引用了两次**：`sakura.js` 在页面里出现两遍，整套模块跑了两次，
  于是注册出两套汉堡菜单的点击监听器 —— 一个负责打开、另一个立刻判定「已经打开了，
  再点就该关」，所以表现为「点不开」。
- **怎么修**：删掉重复的那个内容文件，只留 `content/search.md`，并把它的模板指向
  `layout: "search-page"`；旧地址用 `aliases` 兜一个跳转。
- **怎么验证**：构建日志 0 error 0 warning（说明不能靠日志发现这类问题），
  改为检查产物：页面里必须出现 `search-page`、不能出现 `post-title`；
  并且全站每个页面 `sakura.js` 的引用次数必须是 **1**。另外用真实鼠标事件点汉堡，
  确认 `nav-open` 变 true、5 个菜单项可见、再点能收起。
- 提交：`ba5d10b`、`b4a3cf8`

### 3. 评论区的深浅色不跟站点走

- **现象**：站点切到深色，正文和卡片都变深了，**评论区还是白的**。
- **根因**：两个原因叠在一起。
  1. giscus 配的是 `theme = "preferred_color_scheme"` —— 它跟随的是**操作系统**的深浅色，
     不是站点右上角那个切换按钮。所以系统是浅色时，你把站点切深色，评论不会动。
  2. 更细的一处：我第一版把设置 `data-theme` 的内联脚本放在了 giscus 的
     `<script src=client.js>` **前面**，而脚本要用 `getElementById` 拿那个元素 ——
     此时元素还没被解析出来，取到 `null`，`setAttribute` 直接抛异常，
     属性根本没改上。这个问题在部署后才从浏览器控制台发现。
- **怎么修**：把内联脚本挪到 giscus 的 script 标签**之后**（`client.js` 是 async 的，
  此时它还没执行，改属性完全来得及，所以首帧颜色就是对的、不会先浅后深闪一下）；
  并且把它从「跟随系统」改成读站点自己的主题；切主题时再向 iframe 发一条
  `postMessage` 同步：

  ```js
  f.contentWindow.postMessage(
    { giscus: { setConfig: { theme: t === 'dark' ? 'dark_dimmed' : 'light' } } },
    'https://giscus.app'
  );
  ```

  因为 iframe 是异步插入的，刚打开页面时它还不存在，所以又加了轮询等它出现后补发一次。
- **怎么验证**：在线上分别用浅色和深色截图，并数像素：浅色下评论区平均 RGB 约
  `(243,245,247)`，深色下约 `(33,37,44)`；再确认「深色偏好下全新加载」首帧就是深色
  （`data-theme` 已经是 `dark_dimmed`，不会闪白）。控制台异常数 0。
- 提交：`bc943fd`、`0c9d030`、`8041f66`

### 4. 手机上菜单是白字白底，看板娘挡住评论发送键

- **现象**：手机上展开菜单，文字和背景几乎一个颜色，看不清；另外文章拉到底，
  右下角那只看板娘正好压在评论框的发送按钮上，点不到。
- **根因**：菜单面板是浅色底，**但菜单项的文字颜色没有跟着面板一起改**
  （桌面端的菜单是压在深色 hero 上的白字，那套颜色被小屏复用了）。
  看板娘是 `position: fixed`，在窄屏下它的矩形和评论区的发送键**几何上相交**，
  不只是"看起来挡住了"。
- **怎么修**：菜单面板展开时把菜单项改成深色文字（保留当前页高亮用主题色）；
  看板娘在 ≤1040px 时不再浮动，改成随文档流排在页脚下方 —— 这样它还在，
  但发送键一定点得到。窄屏下的环形进度同时也是 fixed，一并隐藏。
- **怎么验证**：两个宽度下截图比对，并在真机宽度（390）下确认发送键区域没有其它元素覆盖。
- 提交：`86cf152`、`7d88a70`

### 5. 卡片封面把左侧的 MIEW 字标和标题首字裁掉了

- **现象**：列表页卡片右侧的封面图，左边一截被切掉，MIEW 字标和标题第一个字看不见。
- **根因**：封面是 1200×630，而卡片容器比例更「方」，`object-fit: cover` 会左右各裁一半，
  而图里的文字全部靠左（x=88 起），于是正好被裁掉。
- **怎么修**：给封面图加 `object-position: left center` —— 等价于"只从右侧空白处裁"，
  任何视口宽度下文字都不会被切。
- 提交：`eecbb7f`

### 6. 仓库改名之后评论变成 403

- **现象**：文章底部评论加载失败，报 `giscus is not installed on this repository`。
- **根因**：giscus 服务端是**按仓库名**去查 GitHub App 的安装情况的。
  仓库改名之后 `hugo.toml` 里还写着旧名（`Blog`），所以查不到 → 403。
  注意 `repoId` 其实没变，光看 id 对不上会误判成配置没错。
- **怎么修**：把 `[params.giscus]` 的 `repo` 改成改名后的 `MySuperBlog`。
- **怎么验证**：在真实域名下打开文章页，确认 iframe 正常渲染出评论界面。
  （这点很关键：giscus 需要真实域名下的 Discussion，本地 `127.0.0.1` 永远停在加载中，
  所以这类问题只能在线上验证。）
- 提交：`13fc2e5`

### 7. 点首页的粒子文字，粒子是"瞬移"而不是散开

- **现象**：首页那个粒子组成的「MIEW」字样，点一下之后粒子直接出现在屏幕各处，
  没有中间的飞散过程。
- **根因**：散开函数里直接给每个粒子**赋了全屏随机坐标**，等于瞬间传送；
  没有速度、没有阻尼，自然也就没有动画。
- **怎么修**：改成以点击位置为爆心，给每个粒子一个初速度 + 阻尼，再加上拖尾，
  1.4 秒后自己飞回字形。
- 提交：`216d22b`（issue [#3](https://github.com/hehehe1234567894/MySuperBlog/issues/3)）

### 8. 首页只有粒子，正文不见了

- **现象**：首页只剩飘着的粒子，下面的文章列表推到看不见的地方。
- **根因**：粒子用的 `<canvas>` 没有做固定定位，于是它按文档流占了一整屏高度，
  把正文整体顶了下去。
- **怎么修**：给 canvas 加固定定位并铺满视口，`pointer-events: none` 保证不吃点击。

### 9. 文章页重复显示封面 + 界面文案回落到英文

- **现象**：文章页顶部又出现一次封面（列表卡片上已经有过了）；另外部分界面文字变成英文，
  比如 「Table of Contents」「Home › Posts」。
- **根因**：两个独立问题。前者是 `hiddenInSingle` 这个开关没有被正确读取，
  后者是主题的 i18n 词条不全，缺的 key 回落到英文默认值。
- **怎么修**：修好封面的显示判断；并在 `i18n/zh-cn.yaml` 里补齐缺失的词条
  （「目录」「主页」这类）。
- 提交：`d3b043d`

## 三、小结

这 9 个问题里，有 4 个只在手机窄屏出现，2 个只有在真实域名下才能复现，
还有 1 个（搜索页同 URL）是**构建不报任何错**的静默故障。所以这个站的验证习惯是：
改完先在本机按「桌面 / 手机 × 浅色 / 深色」截图看一遍，再上线用同样的尺寸复核一次。
